# Team workflow

Use an issue for each learning question or build milestone. Make small changes on a branch and explain what changed and what evidence supports it.

For documentation, check links between repository files and avoid claiming unbuilt features work. For experiments, include versions, reproduction steps, observed results, and failures.

Add source code and simulation configuration when implementation starts. Keep large generated caches and recordings out of ordinary commits. Document asset provenance and usage rights. Do not upload credentials or machine-specific secrets.

Before merging this starter into an existing repository, compare filenames and preserve existing useful content. The starter is based on the supplied idea pitch; the live repository was not inspected.
